# Redline: AI에게 여러 단계 일을 맡기고 검수하는 연습 (README 초안)

> 제출용이 아닌 초안입니다(11/13 야간 작성). 수치는 `reports/g0/SUMMARY.md`, `reports/spread-compare.md`, `reports/triage-check-*.json`과 G0 보고서(11/12)에서 옮겼고, 사람 검수를 거치지 않은 수치에는 「AI 감사 기준, 사람 확인 전」이라고 적었습니다. 사람 검수 장부가 확정되면 3·5절 수치를 바꿔야 합니다.

## 1. 문제 정의

**사용자.** AI 활용 평가가 들어간 채용을 앞둔 대학생입니다.

**문제.** AI에게 여러 단계로 일을 맡긴 뒤, 어디서 틀렸는지 모른 채 결과를 그대로 내보냅니다. 기업의 AI 역량 평가는 진짜 AI를 주고 그 AI가 저절로 틀린 곳을 지원자가 잡는지를 과정째 봅니다(조사 메모 `1112_기업AI역량평가_방식조사.md`). 그런데 연습할 곳은 대부분 한 번 묻고 한 번 답하는 형식입니다.

**근거.** 같은 업무를 실제 쓰이는 수준의 모델(Claude Sonnet 5.5)에게 다섯 단계로 맡겼을 때, 두 감사가 낸 오류 81항목 가운데 숫자를 잘못 옮긴 것은 0건이었습니다. 많았던 것은 한정어·조건 탈락 22건, 근거보다 큰 결론 18건, 지시 누락 16건, 원자료에 없는 내용 14건입니다(AI 감사 기준, 사람 확인 전). 이런 오류는 앞 단계 결과만 넘겨받은 뒤 단계에서 맥락이 빠지며 생겼고, 원자료와 대조하지 않으면 보이지 않습니다.

**해법.** 맡기기(Delegation), 지시(Description), 검증(Discernment), 책임지고 내보내기(Diligence)를 실제 업무처럼 한 바퀴 연습하게 합니다.
- 사수 모드: AI 동료가 실제로 끝낸 5단계 작업 기록을 원자료와 대조해 틀린 칸에 빨간 줄을 긋고 결재합니다. 채점은 사람이 검수한 오류 장부로만 합니다.
- 팀장 모드: 사용자가 일을 나누고 지시를 쓰고, AI 동료가 실제로 일하면 단계마다 승인하거나 반려합니다. 끝나면 작업 모델과 다른 회사의 모델 두 개가 감사합니다.

## 2. 아이디어 차별성

1. **오류를 심지 않습니다.** 결과물을 손으로 바꾸지 않고, 여러 단계 업무에서 모델이 저절로 낸 오류만 씁니다. 고르는 것은 자료와 지시뿐입니다(각주의 예외, 게시일과 작업일의 차이, 「예정」과 「확정」 등).
2. **정답표를 다른 회사 모델이 만들고 사람이 검수합니다.** 감사는 작업 기록을 처음 보는 새 맥락에서 원자료와 단계별 산출물만 받습니다. 감사 모델은 작업 모델과 다른 회사로 둡니다. 만든 사람이 정답을 보지 않고 먼저 풀어 본 뒤 장부를 검수합니다.
3. **틀린 곳만이 아니라 어디서 생겨 어디로 번졌는지를 돌려줍니다.** 장부 항목마다 처음 생긴 칸과 옮겨진 칸을 적고, 결과 화면에서 「멈췄어야 할 곳」과 「이 오류를 막았을 지시」를 보여 줍니다.
4. **이의 제기가 장부를 고칩니다.** 「장부에 없는 오류다」 「오류가 아니다」를 근거와 함께 보낼 수 있고, 받아들이면 장부 새 판이 생기며 이미 푼 사람의 결과가 다시 계산됩니다.

표시 규칙은 화면·README·발표에서 같습니다: 「AI 감사(두 회사), 사람 확인 전」, 「사람 검수 완료」, 「장부 n판」.

[확인 못 함] 운영 배포에서의 동작(11/13 밤 G2 예정), 휴대폰 실기기.

## 4. 기술 설계·이해도

**흐름(입력 → 처리 → 출력).**
```
미션(원자료 공공누리 제1유형 + 팀장 지시 + 단계 정의)
 → 작업 모델이 단계마다 실행(뒤 단계는 미션이 정한 것만 받음) → 작업 기록(단계별 산출물, 칸 번호)
 → 감사 두세 개(작업 모델과 다른 회사, 새 맥락) → 코드 대조(근거 인용·틀린 구절·숫자·남은 날)
 → 묶기 → 장부 1판(AI) → 만든 사람 검수 → 장부 n판(사람 검수 완료)
 → 사수 모드 채점(A등급만) · 팀장 모드 결과(AI 감사, 점수 없음) · 이의 → 새 판 → 재채점
```

**기술 선택.**
- 모델 호출은 `src/llm.js` 한 곳에서 세 회사(Anthropic·OpenAI·Google)를 같은 모양으로 부릅니다. 구조화 출력(JSON 스키마), 형식 오류 시 사유를 붙여 한 번 재요청, 429·5xx 재시도, 회사별 하루 금액 상한, 호출 기록을 둡니다. 선불 크레딧이 바닥나면(402) 그 회사를 6시간 동안 라이브 경로에서 뺍니다.
- 긴 감사(GPT 고정 판 4~5분)는 스트리밍으로 받아 서버 대기 한도에 끊기지 않게 했습니다. 팀장 모드는 요청 하나에 단계 하나만 돌려 함수 시간 상한(300초) 안에 듭니다.
- 저장은 Upstash Redis(REST)이고, 로컬에서는 메모리(파일 보존 선택)입니다. Vercel Hobby 함수 개수 상한(12개) 때문에 API는 파일 다섯 개(missions, play, lead, review, stats)로 묶었습니다.

**직접 만든 것과 외부 기술.** 미션 실행기, 감사 지시문, 코드 대조(`src/text.js`, `src/audit.js`), 묶기 규칙, 장부 판 관리, 채점(`src/score.js`), 화면은 직접 만들었습니다. 모델(세 회사 API), 저장소(Upstash), 배포(Vercel), 화면 틀(React·Vite)은 외부 기술입니다.

**한계.**
- 감사끼리 보는 폭이 크게 다릅니다(아래 5절). 그래서 채점은 사람 검수 장부로만 합니다.
- 묶기: 11/12까지는 가리키는 칸이 하나라도 겹치면 같은 오류로 묶었습니다. 그 결과 서로 다른 오류가 한 항목이 되고, 한 감사가 넓게 댄 「번진 곳」(G1 판 한 항목 19칸)이 채점 범위가 됐습니다. 11/13부터 새 장부는 근원·틀린 구절이 맞아야 묶고, 번진 곳은 두 감사가 함께 댄 칸만 씁니다(한쪽만 댄 칸은 검수 때 사람이 고르는 후보). 기존 22판에 다시 적용하면 번진 곳 칸 합이 281에서 72로, 장부가 덮는 칸이 265에서 179로 줄었습니다(AI 감사 기준, 사람 확인 전, `reports/spread-compare.md`).

## 5. AI 활용도

**AI가 필요한 이유.** 연습 재료(저절로 생기는 오류)는 AI가 일해야만 생기고, 정답표 초안(감사)도 AI가 만듭니다. 사람은 그 초안을 검수합니다. 참고로 만든 사람이 G1 판 하나(원자료 6건, 5단계)를 정답 없이 푸는 데 기록상 99분(쉬는 시간 포함)이 걸렸습니다.

**주요 기능에 연결된 곳.** 작업 모델(단계별 실제 작업), 감사 모델(장부 1판), AI 1차 판정(사용자의 빨간 줄이 원자료 근거가 있는지, 장부 이유와 같은지 표시만 합니다. 점수에 넣지 않고, 근거가 있다고 본 것은 만든 사람의 대기열로 보냅니다).

**검증.**

| 질문 | 방법 | 결과 |
|---|---|---|
| 감사가 심은 오류를 찾는가 | 결재함 10건(코드가 심은 오류 20개, 정답 확정)을 감사 시험지로 | Claude Opus 5.5 20/20(헛짚음 4), Claude Sonnet 5.5 19/20(6), GPT-6 Astra 20/20(1), GPT-6.1 Sol 19/20(0), Gemini 4 Argon 18/20(2) |
| 감사는 같은 것을 보는가 | m4 기본 판, 작업 모델별 판당 A후보 | Sonnet 판에서 Opus 2·0·1, GPT-6.1 Sol 6·14·11, Gemini 4 Argon 0·0·0(AI 감사 기준, 사람 확인 전) |
| 사람 검수에서 감사가 틀린 비율 | 장부 1판 → 검수 판의 삭제·등급 변경·추가 | [G1 검수 확정 뒤 채움] |
| 이의 제기 결과 | 접수·받아들임 | [운영 뒤 채움] |
| 맡기는 방식이 결과를 바꾸는가 | m4를 대충·기본·잘 맡긴 판 각 2판(작업 세 회사) | 최종본 A후보 평균 대충 3.7 · 기본 5.2 · 잘 3.8(AI 감사 기준, 판 수가 적어 결론 아님) |

시험지 헛짚음 10건을 읽어 보면, 감사가 틀렸다기보다 시험지 쪽에도 저절로 생긴 오류가 있었습니다(예: 「예정」이 빠진 문장). 심은 정답표만으로는 감사를 공정하게 잴 수 없다는 뜻이고, 만든 사람이 장부에 없는 오류를 직접 추가하는 검수 단계를 둔 이유입니다.

## 6. 출처와 이용 조건

원자료는 정책브리핑 보도자료(공공누리 제1유형, 출처표시)의 텍스트이고, 판마다 원문 주소를 밝힙니다. AI 결과물은 손대지 않았습니다. 이름·연락처는 받지 않고, 브라우저가 만든 무작위 번호로만 기록합니다. 만든 사람의 풀이와 시험 판은 통계에서 뺍니다.
